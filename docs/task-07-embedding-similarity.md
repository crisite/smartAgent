# 任务 07：Embedding 与相似度验证

## 目标

把“文本”变成向量，并验证一个问题与两段文本的语义接近程度。这里还没有使用 Qdrant，向量暂时只保存在内存中。

## 运行

在环境变量 `ALI_API_KEY` 中配置阿里百炼 API Key，然后在项目目录执行：

```powershell
.venv\Scripts\python.exe embedding_demo.py
```

示例输出会包含：

- 文档数量；
- 向量维度；
- 向量前 5 个值；
- 每个文档与问题的余弦相似度。

不要把整段向量打印到日志中。向量通常有 1024 个浮点数，完整输出既不利于阅读，也没有调试价值。

## 需要观察的现象

问题是“怎样降低大量数据导出时的内存占用？”，第一段关于离线导出和分批处理的文本通常会得到更高的相似度。分数只用于比较当前候选文本，不能直接当成百分比或正确率。

`EmbeddingService.embed_documents()` 会按每批最多 20 条文本调用百炼，因为 `qwen3.7-text-embedding-flash` 的单批上限是 20 条。后面导入 Markdown 的数百个片段时，这个限制仍然适用。

## 下一步

相似度验证通过后，再用 Docker 启动 Qdrant。Qdrant 负责持久化向量和执行 Top-K 检索；Embedding 模型负责生成向量，两者职责不同。
